# Git 最新状态保留规则

用户要求后续只保留当前状态，避免旧美术版本和额外快照持续占用空间。本规则于 2026-10-20 接续时落盘，适用于本美术项目的后续保存与统一发布。

## 保留范围

当前正式素材、配套设计、必要接入文件和唯一有效在制稿按根 `AGENTS.md` 保留。逐图模型、质量、来源、采用及校验的必要文字记录继续保留；这些文字证据不因清理 Git 历史而删除。

Git 提交本身表示一个文件状态，无法在保留 Git 提交的同时做到零状态记录。发布目标是：正式分支只有一个无父提交，表示最新已核验文件树；不通过普通追加提交累积版本链，也不额外保留素材备份目录、历史分支、标签或 bundle。

## 制作窗口的本地保存

沿已核实基线使用私有对象库和私有 index 记录当前增量，复用未变对象，仅替换一个最新记录。不得改写共享 HEAD、index 或 refs，不把每小时唤醒本身当作需要新增提交的理由。新的最新记录完整且可读后，才清理属于本窗口且已经失效的私有记录；其他窗口的在制稿及在途批次继续保留。

本窗口的有界保存入口为 `node tools/git/save-latest.cjs`。默认只保存根 `AGENTS.md`、本文及工具源码，记录在项目忽略目录 `.work/git-latest-state/history-policy/`；这份记录是明确文件范围的本地增量，不是完整项目、发布基线或上传回执。工具没有网络和推送入口，也没有建立或修改定时任务。

其他制作窗口使用独立名称和稳定文件范围，例如 `node tools/git/save-latest.cjs --slot team-ui docs/example.md`。同一名称的范围不能静默改变；缺失路径不能直接当作有意删除。单次范围上限为 64 MiB，避免把全量迁移批次误送入本地工具。

相同内容重复运行不建立新提交；内容更新后用一个无父提交替换最新记录，核对保存字节后清理这个私有对象库的旧 reflog 和不可达对象。来源目录通过真实路径及链接检查，私有仓库不接受共享对象库、其他 refs 或已有锁。共享 Git 的 HEAD、index、refs 与其他窗口记录保持原样。运行 `node --test tools/git/save-latest.test.cjs` 验证这些行为。

## 唯一上传者的发布流程

1. 从当前明确的采用文件与删除证据确定完整文件集，固定批次和截止点。稀疏缺失、LFS 指针或另一台电脑尚未交接不能作为有意删除的证据。
2. 在私有对象库和 index 中准备一个无父提交。只改变历史结构时，其文件树必须与待替换的已核验提交完全相同；有新增成果时逐项核验来源、依赖、大小和 SHA256。
3. 读取真实远端版本，核对无在途上传和未协调的新版本。使用明确旧版本约束的更新方式，避免覆盖其他上传者的新提交。远端已变时停止覆盖并核对差异。
4. 发布后核对远端提交、单提交结构和完整文件集。需要下载验收的迁移，继续完成独立下载、实际文件大小／SHA256 以及真实 LFS 检查；提交树可读或推送成功不能代替这些验收。
5. 全部核验通过后，由唯一上传者清理本次已失效且无其他用途的本地引用、reflog 和不可达对象。远端历史不可见不等于托管端旧对象／LFS 对象的物理空间已经释放；没有相应证据时不得声称空间已经回收。

## 本次边界与完成判据

- 本规则落盘不等于现有仓库已经改为单提交，也不等于已经提交或推送规则文件。
- 正在捕获／上传的固定批次保持原样，规则进入后续批次；制作窗口不自动接回统一推送职责。
- 现有旧仓、另一台电脑成果和 LFS 数据，在来源完整性与迁移独立下载验收完成前保持原样；不因节省空间而先删旧 `.git`、整包清空缓存或中断其他窗口。
- 完成单提交发布须有实际远端回执、提交数为 1、文件树／清单核对通过及适用的下载验收。只有实际清理且重新测量后，才能报告释放空间。
